# Open Innova Website

Static website for [Open Innova](https://openinnova.it) — open innovation consulting and custom software.

Built with [Hugo](https://gohugo.io), deployed to AWS S3. Bilingual (Italian / English), minimal JavaScript, no cookies, no trackers, no external CDN.

## Quick start

### Prerequisites

- **Hugo extended** v0.100+ — https://gohugo.io/installation/
- **AWS CLI** v2 — only needed for deployment
- **Python 3** and **Google Chrome** — for the accessibility checks (`deploy.sh` installs the rest in `.venv`)

### Local development

```bash
git clone https://github.com/ulivs-app/open-innova-website.git
cd open-innova-website

# Start local dev server with live reload
hugo server

# Visit http://localhost:1313/  (IT)
# Visit http://localhost:1313/en/  (EN)
```

To preview pages marked `draft: true` locally:

```bash
hugo server --buildDrafts
```

### Build for production

```bash
hugo
# Output goes to public/
```

Draft pages are excluded from the production build.

## Project structure

```
├── hugo.toml               # Hugo configuration (baseURL, languages, menus)
├── content/
│   ├── it/                 # Italian pages (default locale, served at /)
│   └── en/                 # English pages (served at /en/)
├── layouts/
│   ├── _default/           # Base templates (baseof.html, single.html)
│   ├── partials/           # Reusable components (head, nav, hero, footer)
│   └── index.html          # Homepage template
├── assets/                 # Processed by Hugo asset pipeline (fingerprinted)
│   ├── css/style.css       # → /css/style.<hash>.css with SRI integrity
│   ├── js/scripts.js       # → /js/scripts.<hash>.js with SRI integrity
│   └── images/             # Logo, og-image — fingerprinted when emitted as URLs
├── static/                 # Files copied verbatim to the site root
│   ├── favicon.svg         # Stable URL (must-revalidate, not immutable)
│   ├── robots.txt
│   └── llms.txt
├── data/
│   ├── company.example.json   # Public template (committed)
│   └── company.json           # Real company data (gitignored)
├── docs/                   # Internal documentation
└── scripts/
    ├── deploy.sh           # AWS S3 deployment (runs the accessibility gate)
    ├── a11y_check.py       # WCAG 2.2 AA checks on the built site (axe + keyboard + reflow)
    └── footprint.py        # Per-visit data, energy, CO₂e and water estimate
```

## Content management

### Adding a page

Create a Markdown file in `content/it/` (and the translation in `content/en/`):

```markdown
---
title: "Page title"
description: "Unique, concise summary for search results"
translationKey: "shared-page-key"
draft: false
---

## Section

Content goes here.
```

URLs are derived from filename:
- `content/it/foo.md` → `/foo/`
- `content/en/foo.md` → `/en/foo/`

### People carousel

On the about pages (`chi-siamo.md`, `about.md`) the team is wrapped in the
`people` shortcode. To add a person, add a `### Name` block (role in bold,
text, contact links) between `{{% people … %}}` and `{{% /people %}}`, in both
languages. Dots, arrows and the "1 of N" labels follow the number of blocks.

### Draft pages

Set `draft: true` in the frontmatter to keep a page out of the production build.
Main-menu and hero links pointing to draft pages are rendered as disabled
`<span>` elements with a work-in-progress tooltip. Links in page content and
the footer need to be checked separately before publishing.

### SEO and metadata

- `<title>` uses the page's `title` frontmatter, suffixed with the site title
  (`Open Innova`). On the homepage the site title is not appended (avoids
  duplication).
- `<meta name="description">` uses the `description` frontmatter when present,
  falling back to the page summary.
- Set the same `translationKey` on corresponding Italian and English pages,
  especially when filenames differ. This connects the language switcher and
  reciprocal `hreflang` links; `x-default` points to the Italian version.
- Keep titles descriptive and descriptions unique. Character counts are an
  editorial aid, not a guaranteed search-result display limit.
- Sitemap (`/sitemap.xml`) and RSS (`/index.xml`) are generated by Hugo.

### Company data

`data/company.json` (gitignored) holds the canonical company facts (legal name,
VAT, addresses, founders, contact emails) used across templates. The committed
`data/company.example.json` is a template — copy it to `company.json` and fill
in the real values.

## Styling

CSS is hand-written, in `assets/css/style.css`. The design system is driven by
CSS custom properties:

```css
:root {
  --color-primary: ...;
  --color-secondary: ...;
  --space-md: 1rem;
  /* ... */
}
```

No CSS framework. The stylesheet passes through Hugo's asset pipeline only
for fingerprinting (see below) — no preprocessor, no PostCSS, no autoprefixer.

### Asset fingerprinting (cache busting)

`assets/css/style.css` and `assets/js/scripts.js` go through Hugo's asset
pipeline. Production builds (`hugo`, the default environment) minify and
fingerprint each file:

```
/css/style.min.0302cad5...3f1fdf7.css
/js/scripts.min.ffa70951...82cec481.js
```

Layouts reference the fingerprinted URL and add the `integrity` (SRI) and
`crossorigin="anonymous"` attributes automatically. When the file content
changes, the hash changes, the HTML reference changes, and browsers fetch the
new file even though both old and new versions are served with
`Cache-Control: immutable, max-age=1y`.

Development builds (`hugo server`, environment `development`) skip both
minify and fingerprint — assets stay at `/css/style.css` and `/js/scripts.js`
so live reload, source maps in DevTools, and SRI-related friction are
avoided. The gate is `{{ if hugo.IsProduction }}` in
`layouts/partials/head.html` and `layouts/_default/baseof.html`.

A repo-level `.gitattributes` forces LF line endings on all text assets to
keep SRI hashes deterministic across machines (a CRLF↔LF flip would change
the hash and break integrity checks in the browser).

To edit CSS, JS, or any image referenced by URL from HTML (logo in JSON-LD,
og-image, etc.), edit the files under `assets/` — **never** under `static/`.
Files in `static/` are copied verbatim and would defeat fingerprinting.

The favicon (`static/favicon.svg`) is the only deliberate exception: browsers,
RSS readers, and mobile home-screen shortcuts expect it at the conventional
`/favicon.svg` path. The deploy script serves it with `must-revalidate` instead
of `immutable` so that changes still propagate on the next page load.

## AI agents and search

- `static/robots.txt` explicitly allows the major AI crawlers
  (GPTBot, ClaudeBot, Google-Extended, PerplexityBot, Applebot-Extended, etc.)
  in addition to standard search engines.
- `static/llms.txt` (served at `/llms.txt`) is a machine-readable summary of the
  company, products, services, and key pages. Keep it in sync when content
  changes.

## Deployment

### To AWS S3

```bash
export AWS_PROFILE=open-innova-deploy
./scripts/deploy.sh
```

The script:

1. Runs `hugo` (excluding drafts)
2. Runs a basic credential scan and the **accessibility checks** (WCAG 2.2 AA): the deploy stops if any page fails — see [docs/accessibility.md](docs/accessibility.md)
3. Syncs `public/` to S3 with proper cache headers
4. Sets HTML to `must-revalidate` (no caching)
5. Sets static assets to 1-year `immutable` cache
6. Invalidates CloudFront (if configured)

See [docs/deployment-aws-s3.md](docs/deployment-aws-s3.md) for the full setup.

### Manual deploy

```bash
hugo
.venv/bin/python scripts/a11y_check.py   # do not deploy if it fails

aws s3 sync public/ s3://openinnova-website \
  --delete \
  --cache-control "public, max-age=31536000, immutable"

aws s3 cp public/ s3://openinnova-website/ \
  --recursive \
  --exclude "*" \
  --include "*.html" \
  --cache-control "public, max-age=0, must-revalidate" \
  --metadata-directive REPLACE
```

## Security

- No credentials in source — `company.json` and any private keys are gitignored
- HTTPS via CloudFront when deployed
- Strict Content Security Policy: only same-origin scripts/styles
- Static HTML only — no server-side code, no database
- S3 bucket policy: `GetObject` only

See [SECURITY.md](SECURITY.md).

## Troubleshooting

### Hugo will not start

```bash
hugo version
# Requires v0.100 or higher, extended
```

### Local changes not showing

```bash
rm -rf resources/ public/
hugo server
```

### Deployment fails

```bash
aws sts get-caller-identity
aws s3 ls s3://openinnova-website/
```

If the deploy script swallows the error, remove the `|| ...` pattern in
`scripts/deploy.sh` temporarily to see the full message.

## Performance

Target: Lighthouse 100/100 on all pages.

- Minimal JavaScript (a few KB of vanilla JS)
- Hand-written CSS, no framework
- System fonts, no Google Fonts
- No external resources, no CDN-hosted libraries
- HTML served from S3, optional CloudFront edge cache

The footprint methodology is described at https://openinnova.it/en/transparency/.
`python3 scripts/footprint.py` measures a served version and applies the
Sustainable Web Design Model v4. Record the date, URL, version and cache/compression
conditions with each run; local preview figures are not production measurements.
Re-run it after changes that affect page weight before publishing numerical claims.

### Environmental narrative and charts

The Italian and English transparency pages share `data/footprint.json`. Update
that snapshot from an identified published release:

```bash
python3 scripts/footprint.py --base-url https://openinnova.it \
  --version-label RELEASE --json-output data/footprint.json
python3 -m unittest discover -s scripts -p test_footprint.py
hugo
```

Replace `RELEASE` with the release identifier or date. Review the exported URL,
date, page count, assumptions and page hashes before publishing. The current
snapshot describes the live site measured on 30 October 2026, before the editorial
rewrite. It deliberately does not claim to measure the page displaying it.
After publishing a new version, measure that version and review a new snapshot;
a local preview must never overwrite production data under a production label.

The `footprint` shortcode renders numbers, cache and model-share charts from this
single dataset. It also exports a downloadable, fingerprinted JSON resource so
updated data cannot be hidden by the long-lived asset cache. The local CSS and
small selector script load only on pages using the shortcode. Without JavaScript,
all charts and the one-million-load scenario remain readable. No visitor counts
or tracking are collected. Water figures represent cooling scenarios only, not
a complete water footprint.
